# 처음 쓰는 사람을 위한 스캔 폼 — 설계

날짜: 2026-09-17

## 문제

스캔 폼이 처음 쓰는 사람에게 어렵다. 첫 화면에 체크박스 다섯 개와 (?) 도움말 다섯 개, 고급 설정에 숫자 아홉 개와 체크박스 두 개, 재수집 줄에 체크박스 하나가 있고, 재수집이 폼의 고급 값을 읽는다는 것까지 알아야 한다. 실제 진단에서 대상·포트·프로토콜 말고 매번 바꾸는 값은 속도(타임아웃·동시 실행·초당 속도)뿐이다.

웹 증적은 가끔 로딩 화면이 찍힌다. `domcontentloaded` 직후에 찍기 때문이다.

## 결정

1. 첫 화면은 다섯 가지: 프리셋 칩, 대상, 포트·프로토콜, 권한 확인, 스캔 시작.
2. 나머지는 접힌 "고급 설정" 안에 만지는 순서대로: 속도 → 탐지 → 승인 범위 → 그 밖.
3. 증적 개수 설정은 없앤다. 증적은 열린 포트 전부. 재수집은 작업 탭의 결과 도구줄로 옮기고, 기본은 빈 곳만 채우기, 전부 다시 찍기는 링크. 재수집은 그 스캔이 원래 쓴 설정을 쓴다.
4. 웹 캡처는 화면이 멈춘 뒤에 찍는다.

## 1. 스캔 폼

### 첫 화면

위에서 아래로: 프리셋 칩(지금 자리) → 대상 → 포트 · 프로토콜 → "스캔 권한을 확인했습니다" → 고급 설정(접힘) → 스캔 시작 · 초기화.

승인 범위는 고급으로 간다. 기본이 "대상을 그대로 승인 범위로 사용"이라 첫 화면에서 볼 일이 없다. 권한 확인 체크박스는 첫 화면에 남는다 — 이것은 설정이 아니라 관문이다.

### 고급 설정

접힌 `<details>` 하나. 열면 네 묶음, 각 묶음에 짧은 제목.

| 묶음 | 항목 | 비고 |
|---|---|---|
| 속도 | 타임아웃(ms), 동시 실행 수, 초당 속도 | 실제로 만지는 값이라 맨 위 |
| 탐지 | 서비스 탐지, 호스트 탐색, UDP 서비스 탐지, TCP Connect 스캔만 사용 | 지금의 체크박스 넷. (?) 도움말은 그대로 |
| 승인 범위 | 대상을 그대로 승인 범위로 사용, 승인 범위 | 지금 그대로 |
| 그 밖 | 상위 포트 수, 제외 대상, UDP 재시도, SYN 재시도, 최대 시도 수, 대형 스캔 승인 | 지금 그대로 |

"고급 N" 배지는 유지한다. 기본값에서 바뀐 항목 수를 센다.

없어지는 것: 증적 수집 개수, 열린 포트 전부 수집, 증적 없는 포트만, 그리고 "선택한 스캔으로" 줄 전체(증적 재수집 · 재수집 중지 · 열린 포트 재스캔).

서비스 탐지 도움말에 "열린 포트마다 증적을 찍습니다. 포트당 1~5초" 한 문장을 더한다. 증적이 얼마나 걸릴지 아는 자리는 여기뿐이다.

### 프리셋

바뀌지 않는다. `PRESET_FIELDS`에 증적 관련 필드가 없었으니 저장된 프리셋도 그대로 쓰인다.

## 2. 증적 개수

스캔 요청은 `screenshot_max: null`을 보낸다. API는 그대로 둔다 — 숫자를 보내는 호출자는 여전히 제한된다. 대시보드만 숫자를 보내지 않는다.

`DEFAULT_SCREENSHOT_MAX = 20`은 API 기본값으로 남는다. 대시보드가 명시적으로 null을 보내므로 영향이 없다.

## 3. 재수집

### 자리

결과 위 도구줄의 "작업" 그룹: `증적 재수집` `열린 포트 재스캔` `취소` `삭제`. 그 아래 한 줄이 상태이자 설명이다.

- 누르기 전: "증적 없는 6개 포트만, 이 스캔의 설정으로. **전부 다시 찍기**" — 링크가 문장 끝에 있다. 빈 곳이 없으면 "증적이 모두 있습니다. **전부 다시 찍기**".
- 누른 뒤: 지금의 진행 문구(`증적 재수집 중… 145 / 1,079 (검사 412) · host:port`)와 중지 버튼.
- 끝난 뒤: 지금의 완료 문구.

"증적 없는 N개"는 선택한 스캔의 결과에서 센다 — 자동 수집 종류의 증적이 없는 열린 포트. 대시보드가 이미 결과 목록을 갖고 있으니 새 API는 없다.

### 설정

재수집 요청은 스캔의 `params_json`에서 `capture_console`과 `screenshot_timeout_ms`를 꺼내 보낸다. 폼은 읽지 않는다. 대시보드가 이미 선택한 작업의 `params`를 갖고 있다.

`screenshot_max`는 null(전부). `missing_only`는 버튼이면 true, 링크면 false.

### 중지

지금과 같다. 재수집 중에는 버튼 자리가 "재수집 중지"가 된다.

### 열린 포트 재스캔

동작은 같다(폼의 대상·포트를 채움). 자리만 옮긴다. 채운 뒤 폼으로 스크롤한다 — 작업 탭에서 눌렀는데 아무 일도 안 일어난 것처럼 보이면 안 된다.

## 4. 웹 캡처 — 화면이 멈춘 뒤에

`domcontentloaded` 뒤, 애니메이션을 멈춘 뒤, 0.4초 간격으로 스크린샷을 찍어 직전 것과 픽셀 차이가 텔넷 칸의 기준(`SSH_PROMPT_STILL_PIXELS`)보다 작으면 그것을 저장한다. 포트 예산(타임아웃 × 2, 기본 16초)이 다 되면 마지막 것을 저장한다 — 지금의 결과와 같다.

첫 비교 대상은 첫 스크린샷이다. 로딩 화면이 첫 장이고 두 번째도 같으면 로딩 화면이 저장된다 — 애니메이션을 멈추면 스피너가 그렇게 된다. 실측해서 그런 페이지가 있으면 `load` 이벤트를 먼저 기다리는 조건을 더한다. 처음부터 더하지 않는 이유: `load`는 폴링하는 관리 페이지에서 늦거나 오지 않고, 안정된 화면 비교가 그것 없이 충분한지부터 알아야 한다.

브라우저 창 캡처(`_capture_browser_window`)와 페이지 스크린샷 양쪽에 적용한다. 비교는 페이지 스크린샷으로 한다 — 창 캡처는 OS 창이라 커서 깜빡임 등 노이즈가 있다.

## 5. 느려지는 결과 조회 — 먼저 재는 것부터

보고: 완료된 스캔을 누를수록 결과 표가 늦게 뜨고, 새로고침하거나 껐다 켜면 낫다.

재현 시도: 통합본(26개 스캔) 위에서 호스트 탭·포트 탭 각각 3바퀴, 78번 클릭. 클릭당 34~68ms로 일정, DOM 노드 1,259개·힙 5MB·살아 있는 타이머 0개 그대로. 백엔드는 지난번에 280회 조회로 22~34ms 일정 확인. 이 환경에서는 쌓이는 것이 없다.

그러니 이번엔 고치지 않고 **잰다**. 다음에 느려질 때 어느 쪽인지 숫자가 말하게 한다.

- 백엔드: 모든 응답에 `Server-Timing: app;dur=<ms>` 헤더. 미들웨어 하나.
- 대시보드: 스캔을 누를 때마다 결과 조회의 서버 시간(`Server-Timing`에서), 전송 시간, 렌더 시간을 재서 최근 30건을 `state.perf`에 둔다. 진단 탭에 표로 보여준다: 시각 · 스캔 · 서버 · 전송 · 렌더 · 행 수. 콘솔에도 한 줄 남긴다.

느려졌을 때 진단 탭을 열면 세 숫자 중 어느 것이 커졌는지 보인다. 서버가 크면 DB·WAL·연결, 전송이 크면 응답 크기, 렌더가 크면 대시보드다.

## 하지 않는 것

- 3선택(없음/대표/전부) 증적 라디오. 증적을 끄는 것은 서비스 탐지를 끄는 것이다.
- 프리셋을 폼 맨 위 큰 선택으로. 칩으로 이미 있고, 첫 화면이 다섯 가지면 충분하다.
- API 변경. `screenshot_max`·`missing_only`는 어제 넣은 그대로.
- 종류별(웹/터미널) 빈 곳 채우기.

## 테스트

- 대시보드 HTML: 첫 화면 필드 목록, 고급 묶음 순서, 증적 개수 필드 부재, 재수집 컨트롤이 결과 도구줄에 있음, 재수집 요청이 `missing_only`·`screenshot_max: null`과 스캔의 params를 보냄.
- 웹 캡처: 가짜 페이지가 두 프레임 뒤에 멈추면 세 번째에 저장, 예산이 다 되면 마지막 것 저장. 실제 Chromium으로 로딩 뒤 내용이 바뀌는 페이지 하나.
- 기존 테스트 중 `screenshot_max: Number(...)`, `scanRecaptureMissingOnly`, `scanScreenshotAll`을 보는 것은 새 구조에 맞게 고친다.

## 확인

패키지된 백엔드로: 열린 포트 두 개 중 하나만 증적이 있는 스캔을 작업 탭에서 선택 → 안내 문구가 "증적 없는 1개 포트만" → 재수집 → 하나만 채워짐 → "전부 다시 찍기" → 둘 다 교체. 3초 뒤에 내용을 그리는 페이지의 웹 증적에 로딩 화면이 아니라 내용이 있음.
