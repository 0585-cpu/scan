# Netroach 결과 통합 관리자 설계

작성일: 2026-09-11  
상태: 설계 승인, 구현 보류  
내부 제품명: Netroach Manager

## 1. 배경과 목표

여러 사람이 Netroach로 포트 스캔을 나눠 수행하면 각 PC에 `netroach.db`와
`netroach-artifacts`가 남는다. 현재는 각자가 보고서를 생성해 전달해야 하므로,
결과를 한곳에서 검색하거나 증적을 함께 확인하기 어렵다.

Netroach Manager는 스캔을 실행하지 않는 별도 Windows 데스크톱 앱이다. 사용자가
여러 `netroach.db`를 등록하면 대응하는 증적 폴더까지 앱 저장소로 복사하고,
모든 결과를 한 대시보드에서 조회·분류·출력하게 한다.

핵심 목표는 다음과 같다.

1. 사용자는 `netroach.db`만 선택하고 증적은 자동 등록한다.
2. 가져온 DB와 증적은 수정하지 않는 원본 복사본으로 보관한다.
3. 검색용 통합 색인을 별도 SQLite DB에 구축한다.
4. 여러 DB의 동일한 호스트·포트를 하나의 논리 결과로 보여주되 모든 관측 이력을
   보존한다.
5. 기존 Netroach의 결과 조회, 증적 미리보기, 보고서와 내보내기 기능을 유지한다.
6. 담당자나 자동 CIDR 분류를 요구하지 않고 사용자가 필요한 경우에만 그룹·태그·
   메모를 추가한다.

예상 규모는 등록 DB 10개 이하, 원본 DB와 증적을 합쳐 수 GB 이하다. 이 범위에서는
외부 데이터베이스 서버 없이 로컬 SQLite로 충분하다.

## 2. 범위

### 포함

- Netroach `netroach.db` 등록 및 앱 전용 저장소 복사
- 동일 위치의 `netroach-artifacts` 자동 탐색과 등록
- 증적 폴더가 다른 위치에 있을 때 수동 지정
- 원본 DB·증적의 무결성 상태와 등록 이력 표시
- 모든 등록 DB 또는 선택한 DB만 통합 조회
- DB 단위 사용자 그룹, 표시 이름과 메모
- 논리 결과 단위 태그와 메모
- IP, 포트, 프로토콜, 상태, 서비스, 날짜, 태그, 증적 유무 검색·필터
- 동일 `IP + 프로토콜 + 포트`의 최신 상태와 전체 관측 이력
- 기존 HTML·Markdown·JSON 보고서
- 기존 JSON·CSV·NDJSON·XLSX 내보내기와 증적 번들
- 등록 원본 단위 무결성 재검사, 증적 보완, 색인 재생성, 등록 삭제
- 별도 Windows 데스크톱 실행 파일과 사용자 데이터 디렉터리

### 제외

- 포트 스캔 실행 및 재스캔
- 패킷 전송, OAST, 라이브 캡처, PCAP 분석 실행
- DB에 보존된 패킷 감사·OAST·PCAP 이력의 통합 색인과 관리 화면
- Nmap, Masscan 또는 다른 제품의 DB·파일 형식
- 자동 CIDR 추정·분류
- 담당자, 계정, 권한, 동시 사용자 협업
- 외부 서버 설치나 인터넷 동기화
- 원본 스캔 결과 또는 원본 증적 수정
- 구현, 패키징, 배포 및 Git 변경 이력 생성

제외된 Netroach 이력도 등록된 원본 DB 안에서는 보존한다. 첫 버전의 관리 화면과
색인이 포트 스캔 결과만 다룬다는 의미다.

## 3. 확정된 설계 원칙

### 3.1 원본 불변 보관

등록된 DB와 증적은 앱 전용 저장소에 한 번 복사한다. 이후 소스 DB는 SQLite
읽기 전용 URI(`mode=ro`)로만 연다. 관리 앱의 API에는 원본 테이블을 갱신하는
경로를 두지 않는다.

IP, 포트, 상태, 서비스, 배너, 오류, 스캔 시간, 원본 태그·메모와 증적 메타데이터는
원본 관측으로 취급한다. 앱에서 추가하는 그룹·태그·메모는 `catalog.db`에 별도로
저장한다.

### 3.2 원본과 색인의 분리

원본 저장소가 증거와 재구축 기준이다. `catalog.db`는 빠른 통합 검색과 관리 상태를
위한 파생 데이터다. 색인이 손상되거나 스키마가 바뀌어도 등록 원본을 수정하지
않고 색인을 다시 만들 수 있어야 한다.

### 3.3 출처 보존

통합 화면에서 결과가 하나로 보이더라도 각 관측에는 다음 출처가 남는다.

- 등록 원본 ID와 표시 이름
- 원본 DB SHA-256
- 원본 스캔 ID와 스캔 상태
- 원본 관측 시간
- 원본 증적 ID, 경로, 크기와 SHA-256

담당자 필드는 만들지 않는다. 원본 파일명과 등록 시각은 감사 정보로만 보관한다.

## 4. 전체 구조

```text
Netroach Manager.exe
├─ WebView2 데스크톱 셸
├─ 127.0.0.1 전용 FastAPI 관리 API
├─ 관리 전용 대시보드 HTML
└─ 사용자 데이터
   ├─ catalog.db
   ├─ staging/
   └─ sources/
      ├─ <source-id>/
      │  ├─ netroach.db
      │  └─ netroach-artifacts/
      └─ <source-id>/...
```

기본 사용자 데이터 경로는 `%APPDATA%\NetroachManager`다. 사용자가 처음 선택한
외부 DB와 증적 폴더는 등록 후 이동하거나 삭제해도 앱의 복사본에는 영향이 없어야
한다.

### 4.1 구성 요소

| 구성 요소 | 책임 |
|---|---|
| 데스크톱 셸 | 앱 실행·종료, 네이티브 파일/폴더 선택, 로컬 API 수명 관리 |
| 관리 API | 등록, 검색, 관리 메타데이터, 증적 전달, 보고서와 내보내기 |
| 원본 어댑터 | Netroach 스키마 확인과 읽기 전용 스트리밍 추출 |
| 등록 서비스 | 임시 복사, 해시, 증적 검사, 원자적 등록과 복구 |
| 색인 저장소 | 통합 검색, 최신 관측 집계, 그룹·태그·메모 저장 |
| 관리 대시보드 | 등록 원본과 통합 결과 조회·분류·출력 |
| 출력 어댑터 | 기존 Netroach 보고서·내보내기 형식 재사용 |

새 앱은 현재 스캐너와 별도 진입점·대시보드·사용자 데이터 경로·설치 프로그램을
가진다. 현재 `netroach.db`를 `SQLiteRepository`로 열면 초기화나 마이그레이션이
발생할 수 있으므로, 등록 원본 읽기에는 별도의 읽기 전용 어댑터를 사용한다.

기존 스캐너 대시보드 파일을 직접 축소하지 않는다. 관리 전용 HTML을 별도로 두고
기존의 한국어 라이트 테마, 결과표, 호스트·상태 탭, 페이지 이동, 증적 뷰어와
출력 경험만 재사용한다. 이 경계는 관리 앱 개발이 스캐너 동작과 사용자 변경분에
회귀를 만들지 않게 한다.

## 5. 저장 모델

정확한 SQL은 구현 계획에서 정하되 논리 테이블은 다음 책임을 가진다.

### 5.1 등록 원본

`registered_sources`

- 내부 `source_id`
- 사용자 표시 이름
- 원본 파일명과 등록 시각
- DB SHA-256와 크기
- Netroach 스키마 버전
- 앱 저장소 상대 경로
- 상태: `ready`, `evidence_missing`, `db_error`, `reindex_required`
- 스캔·결과·증적 수와 누락·불일치 증적 수
- 마지막 무결성 검사 시각과 오류 요약
- 선택적인 사용자 그룹과 소스 메모

`source_groups`

- 사용자가 만든 그룹 이름과 정렬 순서
- 하나의 등록 원본은 그룹이 없거나 한 그룹에 속한다.
- 여러 관점이 필요하면 그룹 대신 다중 태그를 사용한다.

### 5.2 검색 색인

`indexed_scans`

- `source_id + source_scan_id` 복합 출처
- 원본 대상, 포트, 범위, 파라미터와 상태
- 생성·시작·완료 시각과 요약

`indexed_observations`

- `source_id + source_scan_id + host + protocol + port` 복합 출처
- 상태, 서비스, 배너, 오류와 원본 메타데이터
- 원본 관측 시각과 색인 시각

`indexed_evidence`

- 원본 증적 ID와 관측 복합 출처
- 앱 저장소 기준 안전한 상대 경로
- MIME 유형, 크기, SHA-256와 무결성 상태

서로 다른 DB의 ID는 충돌할 수 있으므로 모든 색인 키에 `source_id`를 포함한다.
원본 DB의 정수 행 ID를 전역 식별자로 사용하지 않는다.

### 5.3 관리 메타데이터

`endpoint_metadata`

- 논리 키 `host + protocol + port`
- 사용자 태그, 메모와 수정 시각

원본의 태그·메모는 관측 이력에 그대로 표시하고, 관리자가 추가한 태그·메모는
논리 결과에 덧붙여 표시한다. 두 값을 합쳐서 원본처럼 저장하거나 내보내지 않는다.

## 6. 등록 흐름

### 6.1 정상 흐름

1. 사용자가 하나 이상의 `netroach.db`를 파일 선택기로 고른다.
2. 앱은 각 DB 옆의 `<DB stem>-artifacts`를 찾는다. 일반적인
   `netroach.db`에는 `netroach-artifacts`가 대응한다.
3. 폴더가 없으면 사용자가 다른 증적 폴더를 선택할 수 있다. 선택하지 않아도 DB
   등록은 계속할 수 있다.
4. 원본 DB는 읽기 전용으로 열고 `PRAGMA quick_check`와 필수 테이블·열을 검사한다.
5. DB SHA-256를 스트리밍 계산하고 기존 등록 원본과 비교한다.
6. 원본 DB와 전체 증적 폴더를 고유한 `staging/<source-id>`에 복사한다.
7. DB가 참조하는 증적을 안전한 상대 경로로 해석하고 크기·SHA-256를 검증한다.
8. DB 행을 고정 크기 배치로 읽어 `catalog.db` 검색 색인을 만든다.
9. 파일 복사와 색인 생성이 모두 끝나면 소스 디렉터리를 최종 위치로 전환하고
   대시보드에 공개한다.

등록은 전체 DB나 증적을 메모리에 올리지 않는다. 수 GB 파일에도 진행률, 현재 단계,
복사 바이트, 색인 행 수를 표시하고 사용자가 취소할 수 있어야 한다.

앱이 비정상 종료되면 다음 시작 때 `staging`과 `importing` 상태를 대조한다. 완결된
등록만 복구하고, 불완전한 등록은 대시보드에 노출하지 않은 채 안전하게 정리 가능한
상태로 둔다.

### 6.2 스키마 호환성

필수 테이블과 필수 열이 있으면 알 수 없는 추가 열은 무시한다. 최신 Netroach가
열을 추가했다는 이유만으로 기존 공통 결과를 잃지 않게 한다. 필수 열이 없거나
테이블 의미가 호환되지 않으면 원본을 등록하지 않고 정확한 사유를 표시한다.

`result_evidence_files`가 없는 구버전 DB는 증적 없는 DB로 등록할 수 있다. 원본
DB의 스키마를 관리 앱이 업그레이드하지 않는다.

### 6.3 중복

- 동일 DB SHA-256가 이미 있으면 새 원본을 만들지 않는다.
- 증적이 빠졌던 동일 DB라면 `증적 보완` 작업을 제안한다.
- DB 해시가 다르면 스캔 ID가 겹치더라도 별도 원본으로 등록한다.
- 통합 결과는 논리 키로 묶지만 관측 이력에는 두 출처가 모두 남는다.

## 7. 증적 자동 등록과 무결성

증적 등록은 DB의 `result_evidence_files` 기록을 권위 있는 연결 정보로 사용한다.

- `stored_path`는 반드시 증적 루트 안의 상대 경로여야 한다.
- `..`, 절대 경로, 경로 루트 이탈, 외부를 가리키는 심볼릭 링크나 Windows
  reparse point는 거부한다.
- DB가 기록한 크기와 SHA-256를 실제 파일과 비교한다.
- 참조된 파일이 없으면 `missing`, 해시가 다르면 `hash_mismatch`로 색인한다.
- 증적 폴더 전체는 원본 보존을 위해 복사하지만 DB에서 참조되지 않은 파일은 결과에
  연결하지 않고 개수만 기록한다.
- 불일치 파일은 삭제하거나 정상 증적으로 가장하지 않는다. 대시보드와 출력에서
  경고를 붙여 열람할 수 있다.

DB가 정상이고 일부 증적만 누락·불일치한 경우 등록 상태는 `evidence_missing`이 된다.
DB 결과 검색과 출력은 사용할 수 있으며 누락 수를 항상 표시한다. `증적 보완`은
현재 누락된 참조만 검사해 추가하고, 이미 보관된 파일을 조용히 덮어쓰지 않는다.

증적 제공 API는 색인된 상대 경로만 사용한다. 사용자 입력 경로로 임의 파일을
제공하지 않으며, 지원하는 이미지 MIME과 안전한 다운로드 헤더를 적용한다.

## 8. 통합 결과 규칙

### 8.1 논리 결과

통합 결과의 논리 키는 다음 세 값이다.

```text
host + protocol + port
```

예를 들어 서로 다른 DB에 있는 `10.10.1.15 / tcp / 443` 관측은 대시보드에서 한
행으로 보인다. 원본 행을 합치거나 제거하지 않고 색인 쿼리에서만 논리적으로 묶는다.

### 8.2 최신 관측

대표 행은 관측 시각이 가장 최신인 원본을 사용한다. 관측 시각은 다음 순서로
결정한다.

1. 원본 결과 `created_at`
2. 스캔 `completed_at`, `started_at`, `created_at`
3. 등록 시각

동률이면 `source_id`와 내부 색인 ID로 항상 같은 결과가 선택되도록 한다. 대표 행에는
최신 상태·서비스·배너, 최초·최종 관측 시각, 관측 수, 출처 DB 수와 증적 수를
표시한다.

관측 이력에 둘 이상의 상태가 있으면 `변경됨` 배지를 표시한다. 행을 펼치면 모든
원본 관측을 최신순으로 보여주며 출처 DB, 스캔 상태, 원본 태그·메모, 배너, 오류와
증적을 확인할 수 있다.

## 9. 관리 대시보드

기본 화면은 기존 Netroach의 결과 중심 사용 경험을 유지하되 능동 기능을 제거한다.

```text
┌──────────────────────────────────────────────────────────────┐
│ DB 등록  검색                         보고서 JSON CSV Excel  │
├───────────────┬──────────────────────────────────────────────┤
│ 전체 보기      │ 등록 DB · 스캔 · 호스트 · open · 증적 경고 │
│ 등록 DB 목록   ├──────────────────────────────────────────────┤
│ 사용자 그룹    │ 통합 결과표                                 │
│ 상태 경고      │ IP | Port | Proto | State | Service | 변경 │
│                ├──────────────────────────────────────────────┤
│                │ 선택 결과의 관측 이력 · 증적 · 태그 · 메모 │
└───────────────┴──────────────────────────────────────────────┘
```

### 9.1 상단과 요약

- DB 등록, 전체 검색, 보고서, JSON·CSV·NDJSON·XLSX 출력
- 등록 DB 수, 스캔 수, 고유 호스트 수, 열린 논리 포트 수, 누락·불일치 증적 수
- 현재 선택 범위가 `전체`, 특정 DB 또는 특정 사용자 그룹인지 명시

### 9.2 왼쪽 탐색

- 전체 등록 원본
- 각 등록 원본의 표시 이름, 상태, 등록 시각과 결과 수
- 사용자가 만든 그룹
- `정상`, `증적 누락`, `DB 오류`, `재색인 필요` 상태 필터

자동 CIDR 그룹은 만들지 않는다. 사용자는 등록 원본을 그룹에 직접 배치하고 표시
이름과 메모를 수정할 수 있다.

### 9.3 통합 결과표

- IP·호스트, 포트, 프로토콜, 최신 상태, 서비스, 최신 관측 시각
- 관측 수, 출처 수, 증적 수와 `변경됨` 배지
- 서버 측 검색·필터·정렬·페이지 이동
- 페이지 크기 25, 50, 100, 250, 500
- DB, 그룹, IP, 포트, 프로토콜, 상태, 서비스, 날짜, 태그, 증적 유무 필터

IP 필터는 정확한 주소, 부분 문자열과 사용자가 직접 입력한 CIDR 포함 검색을
지원한다. CIDR 검색은 뷰 필터일 뿐 원본을 자동 분류하거나 저장 구조를 바꾸지 않는다.

### 9.4 상세 영역

- 최신 관측 상세
- 모든 관측의 시간순 이력과 출처
- 상태·서비스·배너 변화
- 원본 증적 썸네일과 앱 내부 전체 화면 미리보기
- 원본 태그·메모와 관리 태그·메모의 구분 표시

### 9.5 제거되는 스캐너 UI

- 대상·포트·범위·권한 입력
- 스캔 시작·취소·복구·재스캔
- 서비스 탐지와 자동 증적 수집 설정
- 패킷, OAST, PCAP, 진단과 벤치마크 실행 화면

## 10. 보고서와 내보내기

기존 Netroach의 출력 형식과 결과 필드를 가능한 한 재사용한다.

- 보고서: HTML, Markdown, JSON
- 결과 내보내기: JSON, CSV, NDJSON, XLSX
- 증적: CSV 증적 ZIP 번들, HTML 증적 포함, XLSX 증적 시트
- 기존 상태·프로토콜·서비스·검색 필터
- 앱 내부 미리보기와 파일 저장

출력에는 두 가지 뷰가 있다.

1. `통합 최신 결과`: 논리 키당 최신 관측 한 건과 관측 수·상태 변경 표시
2. `전체 관측 이력`: 선택 범위의 원본 관측을 출처와 함께 모두 출력

특정 원본과 원본 스캔을 선택하면 기존 단일 스캔 보고서를 생성할 수 있다. 전체나
그룹을 선택하면 통합 보고서를 생성한다. 통합 보고서는 다음 완전성 정보를 명시한다.

- 선택한 등록 DB와 스캔 수
- 원본 관측 수와 논리 결과 수
- 포함·제외된 결과 수와 적용 필터
- 최초·최종 관측 시각
- 누락·불일치 증적 수
- 상태가 변경된 논리 결과 수

통합 최신 결과가 원본 관측을 대체하지 않음을 보고서에 표시하고, 필요하면 전체
관측 이력 형식으로 재출력할 수 있게 한다.

## 11. 관리 작업과 실패 처리

### 11.1 무결성 재검사

등록 원본의 DB·참조 증적 해시와 파일 존재 여부를 다시 검사한다. 외부 원본이 아닌
앱 보관소의 복사본을 검사하며 결과와 검사 시각을 기록한다.

### 11.2 색인 재생성

선택 원본 또는 전체 원본의 파생 색인을 삭제 후 다시 만든다. 그룹·표시 이름·관리
태그·메모는 별도 테이블에 있으므로 재색인으로 사라지지 않는다.

### 11.3 등록 삭제

삭제 전 다음 영향을 표시한다.

- 삭제할 등록 원본 이름과 DB SHA-256
- 스캔·관측·증적 수와 보관 용량
- 삭제 후에도 다른 원본에 남는 논리 결과 수
- 완전히 사라지는 논리 결과 수

사용자가 정확한 원본을 확인한 후에만 해당 `source_id`의 색인과 앱 보관소 복사본을
삭제한다. 처음 선택했던 외부 DB와 증적은 절대 삭제하지 않는다. 파일 삭제에 실패한
경우 성공으로 표시하지 않고 복구 가능한 오류 상태로 남긴다.

### 11.4 오류 표시

오류는 `DB 열기 실패`, `호환되지 않는 스키마`, `복사 실패`, `공간 부족`,
`증적 누락`, `증적 해시 불일치`, `색인 실패`처럼 사용자가 다음 행동을 결정할 수
있는 단계와 원인으로 표시한다. 원본 경로 전체나 민감한 배너 내용은 일반 오류
요약에 노출하지 않는다.

## 12. 로컬 보안 경계

- API는 임의 인터페이스가 아닌 `127.0.0.1`의 자동 선택 포트에만 바인딩한다.
- 앱 시작마다 임의 세션 토큰을 만들고 WebView에는 HttpOnly 쿠키로 전달한다.
- 외부 CDN, 폰트, 스크립트와 인터넷 요청을 사용하지 않는다.
- 원본 DB는 읽기 전용으로 열며 SQL 식별자는 허용 목록으로 제한한다.
- 파일 선택 경로는 정규화하고, 앱 저장소 안의 최종 대상 경로를 다시 검증한다.
- 증적과 보고서에 포함된 배너·메모·파일명은 HTML 이스케이프한다.
- 증적 API는 색인에 등록된 파일만 제공하고 임의 로컬 파일 열기 기능을 두지 않는다.
- 앱에는 능동 네트워크 스캔이나 패킷 전송 코드 경로를 포함하지 않는다.

## 13. API 경계

세부 URL은 구현 계획에서 확정하되 다음 기능 경계를 유지한다.

| 영역 | 기능 |
|---|---|
| 등록 작업 | 등록 시작, 진행 조회, 취소, 중복 확인 |
| 등록 원본 | 목록·상세, 표시 이름·그룹·메모 수정, 삭제 영향 조회와 삭제 |
| 유지보수 | 무결성 재검사, 증적 보완, 선택/전체 재색인 |
| 통합 결과 | 요약, 검색·필터·정렬·페이지 이동, 논리 결과 상세와 관측 이력 |
| 증적 | 썸네일, 미리보기, 안전한 다운로드 |
| 출력 | 현재 선택·필터 기준 보고서와 내보내기 |

수 GB 등록은 요청 하나가 끝날 때까지 기다리는 동기 API로 만들지 않는다. 등록 작업
ID를 반환하고 대시보드가 진행 상태를 조회하도록 한다.

## 14. 성능과 용량 원칙

- DB와 증적 복사는 스트리밍하며 전체 파일을 메모리에 올리지 않는다.
- 색인은 고정 크기 배치로 기록하고 중간 진행률을 제공한다.
- 논리 결과 키와 주요 필터에 맞춘 복합 인덱스를 둔다.
- 모든 결과 목록은 서버 측 페이지 이동을 사용한다.
- 통합 요약은 매 요청마다 원본 DB들을 직접 순회하지 않고 `catalog.db`에서 계산한다.
- DB 10개와 수 GB 원본을 기준으로 기능을 검증한다.
- 최소 1,000,000개 색인 관측의 검색·필터 성능을 자동 측정하고 환경과 측정값을
  기록한다. 특정 하드웨어에서 확인하지 않은 시간을 보편적 성능으로 주장하지 않는다.

- 스트리밍 SHA-256와 동일 DB 중복 감지
- 절대 경로, `..`, 심볼릭 링크·reparse point를 이용한 경로 이탈 차단
- 증적 누락·크기·해시 불일치 분류
- 논리 결과 최신 관측과 동률 결정
- 상태 변경 배지와 관측·출처·증적 수 집계

### 15.2 통합 검증

- 겹치는 호스트·포트가 있는 DB 두 개와 증적 폴더 등록
- 동일 DB 재등록 차단과 누락 증적 보완
- 등록 중 취소·복사 실패·색인 실패 후 반쪽 데이터 부재
- 앱 재시작 후 중단된 staging 복구
- 선택 원본 삭제 후 다른 원본의 결과·증적 유지
- 색인 재생성 후 그룹·태그·메모 유지
- 통합 최신 결과와 전체 관측 출력의 개수·출처 일치

### 15.3 대시보드와 출력 검증

- 기존 Netroach의 결과 필터·페이지 이동·증적 뷰어 동작
- 모든 등록 원본, 개별 원본과 그룹 선택 전환
- HTML 삽입이 가능한 배너·메모·파일명 이스케이프
- HTML·Markdown·JSON 보고서와 JSON·CSV·NDJSON·XLSX 출력
- 증적 번들 경로와 manifest 해시 일치
- 누락·불일치 증적 및 출력 완전성 고지
- 외부 리소스와 새 창 의존성 부재

### 15.4 Windows 패키지 검증

- Python·Rust·Node.js가 없는 대상 Windows PC에서 설치·실행
- WebView2, 로컬 API 시작과 앱 종료 시 프로세스 정리
- 수 GB 등록 중 메모리 사용이 파일 크기에 비례해 증가하지 않음
- 등록 후 외부 원본 폴더를 이동해도 대시보드와 증적이 정상 동작
- 스캐너 엔진·Npcap 없이 관리 기능이 완전하게 동작

## 16. 완료 기준

첫 구현은 다음 조건을 모두 만족해야 완료로 볼 수 있다.

1. 새 앱이 기존 Netroach 스캐너와 별도 설치·실행된다.
2. 사용자가 `netroach.db`를 선택하면 대응 증적을 자동으로 찾아 앱 저장소에 복사한다.
3. 원본 DB를 변경하지 않고 등록 DB 10개를 한 대시보드에서 조회할 수 있다.
4. 동일 `IP + 프로토콜 + 포트`가 한 행으로 보이고 모든 원본 이력과 증적을 열 수 있다.
5. 그룹·태그·메모가 원본과 분리되어 저장되고 재색인 후에도 유지된다.
6. 기존 보고서·내보내기 형식과 증적 포함 기능이 동작한다.
7. 중복, 손상 DB, 누락·불일치 증적, 등록 중 실패가 명시적으로 처리된다.
8. 삭제가 선택한 앱 보관 원본에만 한정되고 외부 원본을 건드리지 않는다.
9. 경로 이탈·임의 파일 제공·HTML 삽입 회귀 검증이 통과한다.
10. 현재 Netroach 스캐너의 동작과 사용자 변경분에 회귀가 없다.

설치 프로그램 생성, 테스트 실행을 위한 구현, Git stage·commit·push가 포함되지 않는다.

작업 트리와 적용되는 `AGENTS.md`를 다시 확인한 뒤 작은 단계로 구현·검증한다.
