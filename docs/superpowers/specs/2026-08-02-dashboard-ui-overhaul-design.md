# 대시보드 UI 개편 설계

작성일: 2026-08-02
대상: `netroach/static/dashboard.html`

## 배경

현재 대시보드는 왼쪽 텍스트 사이드바 + 상단 바 + 세로로 긴 폼 구조다. 오래
앉아 쓰는 도구인데 두 가지가 계속 누적된다.

1. 스캔 하나를 시작하는 데 손이 많이 간다. 폼이 길고, 스크롤해야 결과가 보인다.
2. 진행 상황이 스캔 화면 밖에서는 보이지 않는다.

이 설계는 화면 뼈대를 바꿔 두 병목을 구조로 해소한다.

## 제약

- 빌드 단계 없는 단일 자립 HTML 파일. CDN·외부 폰트·외부 스크립트 금지.
- `target="_blank"` 및 `window.open()` 금지 (Tauri WebView2가 새 창 이동을
  차단한다). 회귀 테스트가 이를 강제한다.
- 라이트 테마 유지. 한국어 UI, 기술 용어는 영문 유지(`open`/`filtered`,
  CIDR, BPF, TCP 플래그).
- 저사양 환경에서 동작해야 한다. 새 런타임 의존성 없음.
- 현재 정보 밀도 유지.

## 1. 셸 구조

```
┌─────────────────────────────────────────────────────────────┐
│ 진행 띠 (스캔 실행 중에만 표시, 모든 화면에서 보임)          │
├──┬──────────────────────────────────────────────────────────┤
│  │  ┌── 명령 패널 (380px) ──┐  ┌── 결과 ──────────────────┐ │
│레│  │ 프리셋 칩             │  │ 진행 + 탭                │ │
│일│  │ 대상 / 포트 / 권한    │  │ 호스트별 실시간 목록      │ │
│  │  │ ▸ 고급 설정 (접힘)    │  │                          │ │
│  │  │ [스캔 시작]           │  │                          │ │
└──┴──└───────────────────────┘  └──────────────────────────┘─┘
```

- **아이콘 레일** (폭 56px): 기존 텍스트 사이드바를 대체한다. 호버 시 라벨이
  펼쳐지고, 현재 화면만 강조된다. 가로 공간을 결과 영역으로 돌린다.
- **명령 패널**: 스캔 화면에만 존재한다. 폭 380px 고정.
- **결과 영역**: 남은 폭 전부. 스크롤 없이 시작하고, 결과가 여기에 쌓인다.

좁은 창(1100px 미만)에서는 두 칸이 위아래로 쌓이고, 명령 패널이 값 요약 한 줄로
접힌다.

## 2. 스캔 시작 절차 — 프리셋

프리셋은 고르면 끝이 아니라, **채워지고 거기서 고치는** 출발점이다. 입력이 매번
조금씩 달라지는 사용 패턴을 프리셋이 감당해야 한다.

### 프리셋 칩

명령 패널 최상단에 한 줄:

```
[빠른 점검] [웹 포트] [전체 정밀] [내부망 *] [+ 저장]
```

- 칩 클릭 = 폼에 값 채움. **자동 시작하지 않는다.** 포커스는 대상 칸으로
  이동하고 전체 선택 상태가 된다 — 한 번 타이핑하면 대상만 덮어써진다.
- 값을 하나라도 고치면 칩에 `*`가 붙고, `저장` 버튼이 `덮어쓰기 / 새로 저장`
  으로 갈라진다.
- 숫자키 `1`~`9`로 선택. 마지막에 쓴 프리셋은 화면 진입 시 자동 선택된다.

### 프리셋에 저장되는 것

| 저장됨 | 저장 안 됨 |
|---|---|
| 포트 지정, 프로토콜, 동시성, 타임아웃, 재시도, 엔진 선택 | 권한 확인 체크 |
| 대상 (`대상도 함께 저장` 체크 시에만, 기본 꺼짐) | 범위 CIDR (대상에서 유도) |

대상은 기본적으로 저장하지 않는다. 매번 달라지므로 프리셋은 "설정 묶음"으로
두고 대상만 매번 입력하는 편이 빠르다.

**권한 확인 체크는 절대 저장하지 않는다.** 저장된 체크가 자동 복원되면 안전
장치의 의미가 사라진다. 프리셋을 적용해도 체크박스는 항상 해제 상태로 시작한다.

### 내장 프리셋 (읽기 전용, 삭제 불가)

- `빠른 점검` — 상위 100포트, TCP, 동시성 보통
- `웹 포트` — 80/443/8000-8090/8443
- `전체 정밀` — 1-65535, 타임아웃 길게, 동시성 낮게

### 사용자 프리셋

`localStorage`에 저장, 최대 12개. 칩 호버 시 `✎ ✕`(이름 변경 / 삭제)가 나타난다.
저장 한도를 넘기면 저장 버튼이 비활성화되고 "12개까지 저장할 수 있음"을 알린다.

### 입력 필드

| 줄 | 내용 |
|---|---|
| 1 | 대상 — CIDR / IP / 호스트명 |
| 2 | 포트 — 드롭다운(상위 100 / 상위 1000 / 전체 / 직접), `직접` 선택 시에만 입력칸 노출 |
| 3 | 권한 확인 체크 + 범위 CIDR (대상과 같으면 자동 채움) |

고급 설정(동시성·타임아웃·재시도·프로토콜·엔진)은 접힌 상태가 기본이다. 접힌
상태에서도 현재 프리셋의 기본값과 다른 항목이 있으면 `고급 2` 배지를 붙여
무엇을 바꿔뒀는지 잊지 않게 한다.

### 제출 전 검증

대상 필드에서 포커스가 빠질 때 즉시 파싱한다.

- 성공: 시작 버튼 위에 `호스트 254개 · 포트 100개 = 25,400 프로브 · 예상 40초`
- 실패 또는 범위 밖: 시작 버튼 비활성 + 해당 줄에만 오류 텍스트

제출 후 에러 배너를 띄우는 현재 방식을 대체한다.

## 3. 진행 표시와 실시간 결과

### 전역 진행 띠

스캔이 실행 중일 때만 나타난다. 높이 36px, 모든 화면에서 보인다.

```
◉ 192.168.0.0/24 · 상위 100  ▓▓▓▓▓▓░░░░ 62%  1,204/1,940  open 18  err 2  00:42  [중지] [열기]
```

- 왼쪽 대상 요약으로 무엇을 돌리는 중인지 즉시 확인된다.
- `open 18`은 열린 포트 누적 수. 실제로 가장 궁금한 정보다.
- 띠 아무 곳이나 클릭하면 해당 스캔 화면으로 이동한다.
- 동시 실행이 여러 개면 `+2` 배지가 붙고, 클릭 시 목록 드롭다운이 열린다.
- 완료 시 3초간 초록으로 `완료 · open 23`을 표시하고 사라진다. 실패는 적색으로
  남으며 사용자가 직접 닫아야 한다.

### 스캔 화면의 결과 영역

시작을 누르는 순간 오른쪽 칸이 결과 뷰로 바뀐다. 화면 전환은 없다.

```
진행: ▓▓▓▓▓░░░ 62%    [호스트 12] [열린 포트 18] [로그]
──────────────────────────────────────────────────
192.168.0.1     open 80,443        ● 완료
192.168.0.7     open 22            ● 완료
192.168.0.14    스캔 중… 41/100    ◐
192.168.0.15    대기               ○
```

- 호스트 단위로 줄이 추가되고, 각 줄이 자기 진행도를 가진다.
- 열린 포트가 발견되면 그 줄이 0.6초간 배경 강조된다. 오래 보고 있을 때 새로
  뜬 항목을 놓치지 않게 한다.
- 기본 정렬은 **열린 포트가 있는 호스트 우선**, 그다음 발견 순. 254개 스캔에서
  결과 있는 3개를 찾으려고 스크롤할 일이 없다.
- 탭: `호스트 / 열린 포트 / 로그`. `열린 포트` 탭은 호스트 구분 없이 포트
  목록을 평평하게 보여준다.
- 스크롤을 위로 올려두면 자동 스크롤이 멈추고 `새 결과 12건 ↓` 버튼이 뜬다.
  읽는 중에 화면이 튀지 않게 한다.

### 갱신 방식

새 의존성 없이 현재의 폴링을 유지하되 간격을 상황에 맞춘다.

| 상태 | 간격 |
|---|---|
| 실행 중 + 탭 활성 | 700ms |
| 실행 중 + `document.hidden` | 5s (진행 띠 숫자만 유지) |
| 실행 중인 스캔 없음 | 정지 |

저사양 환경을 고려해 DOM은 전체를 다시 그리지 않고 변경된 줄만 교체한다. 호스트
200개를 넘으면 화면 밖 줄은 렌더를 생략한다.

### 실패와 부분 실패

호스트 줄에 `● 오류` 상태를 따로 둔다. 전체 진행은 계속되고, 오류 개수는 진행
띠에 `err 2`로 붙는다. 스캔이 통째로 실패한 것과 호스트 하나가 실패한 것을
구분해 보여준다.

## 4. 단축키

입력칸에 포커스가 있을 때는 숫자키와 단일키 단축키를 비활성화한다 — 타이핑을
방해하지 않는다.

| 키 | 동작 |
|---|---|
| `1`~`9` | 프리셋 선택 |
| `Ctrl+Enter` | 스캔 시작 (입력칸 안에서도 동작) |
| `Esc` | 오버레이 닫기 / 고급 설정 접기 |
| `t` | 대상 칸 포커스 + 전체 선택 |
| `g` → `s` / `p` / `r` | 화면 이동 (스캔 / 패킷 / 리포트) |
| `?` | 단축키 목록 오버레이 |

`Ctrl+Enter`는 권한 확인이 안 된 상태에서는 시작하지 않는다. 체크박스에 포커스를
주고 짧게 흔든다.

## 5. 시각 언어

라이트 테마를 유지하되 기존과 명확히 구분되게 한다.

- **강조색**: 파랑 `#1b6ec2` → 진한 청록 `#0f766e`.
- **상태색** (의미 고정): `open` 청록, `filtered` 회색, `closed` 연회색,
  오류 `#b91c1c`.
- **배경**: 순백 대신 `#f7f8f7`, 카드만 흰색. 두 칸 레이아웃에서 선 없이 영역이
  구분된다.
- **테두리 대신 면**: 1px 선을 거의 없애고 배경 톤 차이로 영역을 나눈다. 화면이
  조용해져 장시간 사용 피로가 준다.
- **타이포**: 대상·포트·IP 등 값은 전부 등폭(`ui-monospace`). 자릿수가 맞아
  목록을 훑을 때 시선이 흔들리지 않는다. 라벨은 본문 폰트 12px 회색 — 라벨을
  작게, 값을 크게.
- **모서리**: 4px로 통일 (현재 8~12px 혼재). 각진 형태가 도구처럼 보인다.
- **간격**: 밀도는 현재 수준 유지. 4px 배수로 통일해 줄 높이의 불균일만 정리.
- **움직임**: 새 결과 강조 0.6초, 오버레이 열림 120ms. 그 외 애니메이션 없음.
  `prefers-reduced-motion`에서는 전부 끈다.

## 테스트

`tests/test_dashboard.py`를 확장한다. 대시보드가 정적 자산 하나이므로 검증은
문자열/구조 수준에서 이뤄진다.

- 기존 회귀: `target="_blank"`와 `window.open` 부재.
- 외부 리소스 부재: `http://` / `https://` 로 시작하는 `src`·`href` 없음.
- 내장 프리셋 3개가 문서에 존재한다.
- 권한 확인 필드명이 프리셋 직렬화 대상 목록에 없다 — 안전 장치가 저장되지
  않음을 코드 수준에서 고정한다.
- 폴링 간격 상수(700ms / 5s)와 `document.hidden` 분기가 존재한다.
- 단축키 표의 각 키가 핸들러에 등록되어 있다.

기존 API·리포트 테스트는 변경하지 않는다. 이번 작업은 프런트엔드에 한정되며
백엔드 계약을 바꾸지 않는다.

## 범위 밖

- 다크 테마 (라이트 유지 결정)
- 스캔 큐 / 예약 실행
- 프리셋의 서버 측 저장·동기화 (`localStorage`로 충분)
- 백엔드 API 변경
